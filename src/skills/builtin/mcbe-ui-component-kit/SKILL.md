# Componentes reutilizáveis JSON UI

Inspecione o pack, a versão e os padrões que já existem. Proponha componentes namespaced
parametrizáveis (por exemplo botão, linha, card, grid ou form) com contrato explícito de
variáveis, dimensões, callbacks, bindings e estados. Separe layout de comportamento para
que consumidores possam substituir dados sem copiar telas inteiras.

Não assuma que o jogo suporta imports/modularidade como uma biblioteca de UI web. Implemente
reuso pela herança/namespace e arquivos aceitos pela versão, validando no runtime quando
possível. Preserve compatibilidade com telas existentes, explique as limitações da API e
inclua um exemplo consumidor e uma matriz simples de parâmetros.

Não copie skills/código/templates do repositório externo sem licença declarada. O conteúdo
deve ser original e baseado em documentação pública; não redistribua assets vanilla.
